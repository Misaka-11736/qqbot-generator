# 架构

## 两个包

```
src/
├─ qqbot_core/          # 机器人内核，和界面完全解耦，可单独跑
│  ├─ config.py         #   TOML 配置 <-> dataclass
│  ├─ onebot.py         #   OneBot 11 正/反向 WebSocket
│  ├─ message.py        #   事件解析（数组段 / CQ 码）
│  ├─ engine.py         #   触发判定、上下文、调模型、发送
│  ├─ persona.py        #   人格提示词 + 六档智商
│  ├─ intent.py         #   task/chat 意图门
│  ├─ semantic.py       #   动作/量词/主体/输出/发送
│  ├─ memory.py         #   会话历史与设置（JSON）
│  ├─ llm.py            #   OpenAI 兼容客户端 + 离线 MockBrain
│  └─ util.py           #   日志、限流、清洗、原子写
└─ qqbot_generator/     # PySide6 界面
   ├─ app.py            #   主窗口、顶栏、托盘
   ├─ theme.py          #   颜色、QSS、阴影
   ├─ paths.py          #   开发/打包两种路径
   ├─ context.py        #   AppContext：页面只依赖它
   ├─ pages/            #   9 个页面，注册表在 pages/__init__.py
   ├─ widgets/          #   图标、吉祥物、卡片、侧栏
   └─ services/         #   配置、进程、日志、NapCat、自检、试聊、自启
```

## 进程模型

```
QQ Bot生成器.exe（GUI 进程）
   │  点「启动机器人」
   ├─ subprocess: 同一个 exe --run-bot --config ...   ← 机器人内核
   │     └─ asyncio + OneBot WebSocket
   └─ 日志文件 logs/bot-*.log ← GUI 每 0.7s 增量读取
```

为什么用子进程而不是线程：

- 内核崩了不会带走界面；
- 退出界面时能干净地终止内核；
- 打包后一个 exe 同时是「界面」和「内核」，不需要额外装 Python。

`--run-bot` 模式下不 import 任何 Qt 代码，启动快、内存小。

## 数据流

1. NapCat 把 QQ 消息转成 OneBot 事件，经 WebSocket 推给内核；
2. `message.parse_event` 解析出会话键、是否 @、引用、文本；
3. `engine` 判断要不要回（私聊必回、群聊 @/引用/概率）；
4. `persona.build_system_prompt` 拼人格 + 智商档位 + 场景 + 规则；
5. `llm` 调 OpenAI 兼容接口（或离线大脑）；
6. 清洗、按长度拆段、模拟延迟；
7. 调 `send_group_msg` / `send_private_msg` 发回 NapCat。

## 线程 / 协程

| 位置 | 模型 |
| --- | --- |
| 机器人内核 | 单进程 asyncio，每条消息一个 task，会话级锁保证顺序 |
| 试聊页 | 独立线程跑 asyncio loop，信号回主线程更新气泡 |
| 模型测试 / 人格预览 / NapCat 下载 | `QThreadPool` + `QRunnable`，避免卡界面 |
| 日志跟随 | 主线程 QTimer 增量读文件 |

## 配置与路径

- 开发时：`src/` 直接 import，数据默认写 `%LOCALAPPDATA%\QQBotGenerator`；
- 打包后：`_MEIPASS` 放只读资源（人格、图标），数据仍写用户目录；
- `QQBOT_DATA_DIR` 环境变量可以覆盖数据目录（测试用）。

## 扩展点

| 想加什么 | 改哪里 |
| --- | --- |
| 新页面 | `pages/xxx.py` 继承 `BasePage`，在 `pages/__init__.py` 注册 |
| 新配置项 | `qqbot_core/config.py` 加字段 + `toml_dump`，页面加控件 |
| 新指令 | `qqbot_core/commands.py` 的 `_COMMANDS` 表 |
| 新模型服务商 | 模型页的 `PRESETS`（只是填地址和模型名） |
| 新消息类型（图片理解等） | `message.py` 解析 + `llm.py` 多模态消息 |
| 新的人格档位 | `persona.py` 的 `TIERS`，保证区间连续（测试会检查） |

## 错误处理约定

- 模型失败：日志记原因，群里回一句兜底，不把 HTTP 错误甩给用户；
- 发送失败：只记日志，不重试，避免重复消息；
- NapCat 断线：反向模式等它重连；正向模式退避重连；
- 端口被占：启动前检查，直接提示换端口；
- 配置损坏：`JsonStore` 备份为 `.corrupt.json`，不覆盖用户数据。
